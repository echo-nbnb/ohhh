### 项目概述

**寻麓千年色** 是一个以湖湘文化为底蕴的 **智能交互装置**。

用户通过**手部动作**全程与投影画面交互——摄像头实时捕捉手部 21 个关键点，AI 识别手势意图（绘画、选择、浏览、确认），驱动四幕叙事体验。从选择颜色、手势绘画物象，到 AI 推荐历史人物、生成个性化精神画像，形成完整的沉浸式文化叙事体验。

整个体验链路兼顾**实时性**（逐帧手部追踪 <50ms 延迟）与**高质量内容生成**（RAG 检索 + LLM 归因 + 云端生图）。

### 核心概念

**"寻麓千年色"** —— 不是在找颜色，而是在寻找湖大千年精神中属于"我"的那一抹色彩。

- **寻**：探索、追问、对话
- **麓**：岳麓，根脉所在
- **千年**：从张栻到今天的精神传承
- **色**：不只是颜色，更是精神底色

**最终输出：一段专属于玩家的个性化叙事** —— AI 根据玩家的选择，为其编织的"精神自画像"。

## 🎭 交互设计

### 交互方式：纯手势驱动

用户全程通过**手部动作**与投影画面交互，无需物理模块。摄像头捕获手部 21 个关键点（MediaPipe），实时识别手势并驱动四幕叙事。

### 手势定义

#### 全局手势（任意阶段可用）

| 手势 | 识别方式 | 效果 |
|------|---------|------|
| 握拳挥动 | 五指握拳 + 手部移动 | 颜色在画作中扩散/晕染 |
| 五指张开 | 五指伸展 | 停止晕染 / 取消当前操作 |

#### 绘画手势（第二幕）

| 手势 | 识别方式 | 效果 |
|------|---------|------|
| 食指伸出 | 仅食指伸展，其余四指握起 | 进入绘画模式，食指尖为笔尖，轨迹实时渲染 |
| 握拳 | 五指全部握起 | 结束绘画 / 确认选中候选物象 |
| 五指张开 | 五指全部伸展 | 取消绘画，清空轨迹 |

#### 选择手势（第二幕/第三幕）

| 手势 | 识别方式 | 效果 |
|------|---------|------|
| 手悬停于候选区上方 | 手掌中心在目标区域内 | 目标高亮、放大、金色边框 |
| 握拳（悬停状态下） | 悬停 + 握拳 | 确认选中当前目标 |
| 五指张开（选中状态下） | 五指伸展 | 取消选中，返回候选列表 |

#### 轮盘手势（第三幕轮盘模式）

| 手势 | 识别方式 | 效果 |
|------|---------|------|
| 手左右滑动 | 手掌水平位移速度 > 阈值 | 轮盘卡片横向滚动，速度与手速正相关 |
| 手悬停 > 1秒 | 手部静止检测 + 计时 | 卡片放大，显示人物名 + 朝代 + 简介 |
| 握拳 | 悬停 + 握拳 | 确认选中人物 |
| 五指张开 | 五指伸展 | 退出轮盘，回到推荐阶段 |

### 四幕叙事流程

```
开场引入 → 第一幕:择色 → 第二幕:筑景 → 第三幕:唤灵 → 第四幕:成色 → 尾声
```

#### 开场引入
- 全黑缓缓亮起，湖大校门剪影水墨晕染浮现
- 泛黄邀请函飘落："岳麓千年，色隐其中。后来者，汝心何色？"
- AI 旁白欢迎玩家 → 摄像头检测到玩家 → 六个颜色桶虚影悬浮

#### 第一幕：择色——"我选择的底色"
- 用户将物理颜色牌放置在桌面（岳麓绿/书院红/西迁黄/湘江蓝/校徽金/墨色）
- **YOLO 实时检测**颜色牌的类型 + 位置 → 发送 Unity
- Unity 在对应位置渲染光圈绽放，颜色基调充满投影面
- 每种颜色有独立的 AI 旁白、画面意象和音效
- 备选：手势悬停虚拟颜色桶选择（无实物时）

#### 第二幕：筑景——"我看见的世界"
- 食指伸出进入绘画模式，指尖光点轨迹实时渲染
- 握拳结束绘画 → 轨迹栅格化 28x28 → CNN(QuickDraw MobileNet) 分类
- 345 类 QuickDraw 映射 88 物象 → 颜色上下文加权 → Top-3 候选浮现
- 悬停 + 握拳确认选中物象，五指张开放弃重画
- 可放置多个物象（建议 1-3 个），物象间可建立连接线

#### 第三幕：唤灵——"我听见的声音"
- **阶段一（推荐）**：RAG 检索颜色+物象 → LLM 排序 Top-3 人物卡片浮现
- 悬停预览人物简介 → 握拳确认选中 → 光柱冲天而起
- **阶段二（轮盘）**：五指张开拒绝推荐 → 进入轮盘模式
- 5 组 160 人物横向滚动浏览（古代先贤/近代湖湘/现代学人/校园角色/抽象意象）
- 选中人物后，AI 以人物第一人称独白，多人物可触发对话

#### 第四幕：成色——"这是属于我的千年色"
- 自由调整阶段：移动物象、建立连接、手势晕染
- 放置"确认章"触发最终生成
- RAG 检索 → 个性化叙事文本 → LLM 归因 → 云端 API 生图
- 最终画作呈现 + 精神画像叙事 + 二维码带走数字资产

> 完整情境细节（AI 旁白文本、色彩意象、人物独白等）见 [`proposal/interaction.md`](proposal/interaction.md)

### 颜色牌检测管线（第一幕）

```
摄像头俯拍桌面
        ↓
YOLOv8n 实时检测（6 类颜色牌，BoT-SORT 跨帧跟踪）
        ↓
输出：类型 (class_id) + 像素位置 (bbox center)
        ↓
坐标映射：摄像头像素 → Unity 画布坐标 (1920x1080)
        ↓
发送 Unity → 触发对应颜色的光圈绽放 + AI 旁白
```

> **当前状态**: 颜色牌检测已升级为 **颜色+纹路双保险识别**。
> - YOLOv8n 定位卡片区域
> - HSV 颜色直方图匹配（辅助）
> - PiDiNet 边缘检测 + 纹路模板匹配（核心）
> - 融合权重：颜色 0.4 + 纹路 0.6
>
> 训练流程见下方 **训练教程** 章节。

### 物象识别管线（第二幕）

```
MediaPipe 食指指尖轨迹（点序列）
        ↓
轨迹栅格化：28x28 灰度图，笔画宽度 2px
        ↓
CNN 推理（QuickDraw 预训练 MobileNet，345 类）
        ↓
QuickDraw 类别 → 88 物象知识库映射
        ↓
颜色上下文加权（第一幕颜色对候选物象加权/降权）
        ↓
返回 Top-3 候选物象（Top-1 居中高亮，金色边框）
```

### 人物推荐管线

```
第一幕颜色 + 第二幕物象
        ↓
RAG 检索人物知识库（160 条目，BM25 + 语义匹配）
        ↓
LLM 排序 Top-3 推荐人物
        ↓
用户确认 / 拒绝后进入轮盘自选（5 组 160 人物）
```

### 连接类型矩阵

| 连接类型 | 组合 | 视觉样式 | 叙事逻辑 |
|---------|------|---------|---------|
| 精神共鸣 | 颜色 to 颜色 | 金色虚线 | 情感混合，产生新内涵 |
| 精神赋予 | 颜色 to 物象 | 物象对应色光线 | 颜色赋予物象情感解读 |
| 人格染色 | 人物 to 颜色 | 人物对应色光线 | 人物特质影响颜色解读 |
| 场景进入 | 物象 to 人物 | 白色实线 | 激活历史典故 |
| 意境叠加 | 物象 to 物象 | 白色实线 | 意象联想，产生新场景 |
| 精神对话 | 人物 to 人物 | 青色实线 | 对话、师承、对比关系 |

### 画作风格决策

| 人物年代 | 推荐风格 | 说明 |
|---------|---------|------|
| 古代（朱熹等） | 水墨写意 | 符合历史质感 |
| 近现代（李达等） | 老照片实景 | 穿越感 |
| 混合年代 | 穿越风格 | 古今同框 |

### 叙事生成逻辑

```
用户选择（颜色+物象+人物+连接）
        ↓
构建连接关系图 → 提取核心元素（连接数最多）
        ↓ （无法提取时）
按连接类型优先级保底：
  spirit_dialogue > personality_dye > scene_entry
  > color_grant > scene_combination > spiritual_resonance
        ↓ （复杂场景降级）
LLM 自由发挥
        ↓
生成个性化叙事 + 生图提示词 → 云端 API 生成最终画作
```

> **MediaPipe Hand Landmarker：21 个手部关键点，逐帧追踪**

| 项目 | 内容 |

| 状态模式 | 说明 |

#### 2.2 知识库结构

```
rag/knowledge/
├── entities/                    # 实体定义
│   ├── colors.json            # 6 颜色含义与意象
│   ├── objects.json           # 88 物象典故与映射
│   └── characters.json        # 160 人物故事与对话
├── combinations/               # 组合解读
└── templates/                 # 叙事模板
```

#### 2.3 关键模块

| 模块 | 文件 | 功能 |
|------|------|------|
| 颜色牌检测 | `vision/color_card_detector.py` | YOLOv8n 实时检测 6 种颜色牌的**类型 + 位置** |
| 检索引擎 | `rag/retriever.py` | BM25 + 语义匹配，从知识库检索相关内容 |
| 叙事生成 | `rag/generator.py` | 基于检索结果生成 AI 旁白文本 |
| 人物推荐 | `rag/character_recommend.py` | 颜色语义 + 物象关联 → 人物知识库匹配 → LLM 排序 |
| 物象桥接 | `unity_bridge/sketch_bridge.py` | CNN 分类结果 → 88 物象映射 → 颜色加权 Top-3 |
| 人物桥接 | `unity_bridge/character_bridge.py` | RAG 检索 → LLM 排序 → Top-3 推荐卡片 |

| no-display 模式（test_integrated_fast.py） | 去掉 OpenCV 显示开销 |

## 📚 训练教程

> 本教程详细介绍颜色牌检测模型的训练流程。包括模板采集、YOLO 训练和部署。

### 训练流程总览

```
阶段 1：采集模板（必做）→ 阶段 2：标注数据（YOLO定位用）→ 阶段 3：训练 → 阶段 4：部署验证
```

---

### 阶段 1：采集模板（必做）

模板用于**纹路识别**（PiDiNet 边缘匹配），每种颜色牌采集一次即可。

#### 1.1 使用 IP 摄像头采集

```bash
python -c "
from vision.ipcamera import IPCamera
from vision.color_card_detector import collect_templates

cam = IPCamera('http://你的摄像头IP:8080/video')
cam.connect()
collect_templates(lambda: cam.read_frame())
"
```

#### 1.2 使用本地摄像头采集

```bash
python vision/color_card_detector.py
```

**操作说明**：
| 按键 | 操作 |
|------|------|
| `SPACE` | 对准颜色牌按空格拍照（建议 3-5 张不同角度） |
| `N` | 采集完毕，跳到下一种颜色牌 |
| `Q` | 退出采集 |

#### 1.3 采集顺序

按以下顺序依次放置颜色牌拍照：
1. 岳麓绿
2. 书院红
3. 西迁黄
4. 湘江蓝
5. 校徽金
6. 墨色

#### 1.4 采集要求

- **光照**：尽量在展览现场同款灯光下采集（暗光环境）
- **角度**：每种颜色牌拍 3-5 张，覆盖不同角度（正视、侧视、轻微倾斜）
- **背景**：尽量包含展示台桌面的纹理，增加识别鲁棒性

#### 1.5 输出

采集完成后生成文件：`vision/color_card_templates.npz`

### 阶段 2：标注数据（YOLO 定位用）

YOLO 用于**定位**颜色牌在画面中的区域，与纹路识别配合使用。

#### 2.1 准备照片

将颜色牌照片放入数据集目录：

```

└── images/
    └── train/
        ├── yuelu_green_001.jpg
        ├── yuelu_green_002.jpg

        └── ...
```

**建议数量**：每种颜色牌 30-50 张，涵盖不同光照、角度、背景。

#### 2.2 安装标注工具

```bash
pip install labelImg
```

#### 2.3 开始标注


**标注设置**：
- 点击 **Change Save Dir**，选择 `dataset/labels/train`（LabelImg 会自动生成同名 .txt 文件）
- 点击 **View**，勾选 **Auto Save Mode**（切图时自动保存）
- 格式选择 **YOLO**（右下角）

#### 2.4 标注规范

| 类别 | 标签名 | 说明 |
|------|--------|------|
| 0 | yuelu_green | 岳麓绿 |
| 1 | academy_red | 书院红 |

**标注要求**：
- 紧贴颜色牌边缘，不留多余空白
- 每张图只标一个颜色牌（如果有多个都标）

### 常见问题

#### Q1: 模板采集时报错 "PiDiNet 加载失败"

PiDiNet 是备选方案，不影响模板采集。继续使用 Canny 边缘检测即可。

#### Q2: YOLO 训练时显存不足

降低 batch 大小：
```python
results = model.train(..., batch=4, ...)  # 从 8 降到 4
```

#### Q3: 检测准确率低

1. **模板不足**：增加模板采集数量，每种颜色牌采集 5-10 张
2. **标注数据少**：增加训练数据量，每种至少 50 张
3. **光照差异大**：在展览现场同款灯光下采集模板

#### Q4: 颜色和纹路识别结果不一致

双保险融合策略：
- **一致** → 高置信，返回加权平均
- **不一致** → 优先纹路（权重更高 0.6），降低置信度

### 技术细节：颜色+纹路双保险

展览环境光照暗，**仅靠颜色识别不可靠**，采用双保险方案：

```
摄像头帧
    │
    ▼
┌─────────────────┐
│  YOLOv8n 检测     │  ← 定位颜色牌区域（bbox）
│  (定位)          │
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│   裁剪卡片区域    │
└────────┬────────┘
         │
         ├────────────────────┐
         │                     │
         ▼                     ▼
┌─────────────────┐   ┌─────────────────┐
│   颜色识别器      │   │   纹路识别器      │
│  HSV 直方图匹配  │   │ PiDiNet+模板匹配 │
│  (辅助 0.4)     │   │  (核心 0.6)     │
└────────┬────────┘   └────────┬────────┘
         │                     │
         └──────────┬──────────┘
                    ▼
            ┌───────────────┐
            │   决策融合     │
            │ color × 0.4   │
            │  + edge × 0.6 │
            └───────────────┘
```

**各颜色牌预期纹路特征**：

| 颜色牌 | 纹路特征 |
|--------|---------|
| 岳麓绿 | 竖条纹/松针纹理 |
| 书院红 | 横向砖纹/瓦片 |
| 西迁黄 | 折线条纹/地图纹理 |
| 湘江蓝 | 波浪纹理/水纹 |
| 校徽金 | 光泽渐变/徽章边缘 |
| 墨色 | 泼墨/浓淡渐变 |
